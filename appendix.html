## 專案性質

這是一份**企業內部的資安治理文件庫**，同時是**控制項與政策的單一真實來源（single source of truth）**。
文件編號 GSMD-RPT-2026-0830-01。讀者為資安治理決策層與技術落地層。

## 不可違反的規則

### 1. 證據分級是強制的
每一個事實性陳述都必須標註以下四種等級之一：
- 【已證實】= 一手/官方來源（標準機構官方頁、法規正式文本、主管機關新聞稿、上市公司財報或 SEC 申報、法院判決、受害組織官方聲明）
- 【廠商主張】= 具名廠商自行發布的研究或行銷數據，未經獨立驗證
- 【第三方評論】= 具名分析機構、測試機構或主流媒體的評論與整理
- 【尚未證實】= 廣泛流傳但無法回溯至可靠來源，或來源互相矛盾

**未標註等級的事實性陳述，視為錯誤，必須修正。**

### 2. 無來源不列入
若無法取得可靠來源，**不要寫入正文**。改為記錄在 `registry/verification-gaps.yml`。
絕不使用「據報導」「一般認為」「業界普遍」等模糊歸因來規避查證。

### 3. 口徑一致才可比較
不同來源的數字若口徑不同（例如 SEC 申報的增量費用 vs 媒體含營收損失的估計），
**不可放在同一張表或同一句話中比較**。必須註明口徑差異。

### 4. 方法一致才可畫趨勢
若跨年度調查的樣本數或題目定義改變（且來源未說明），**只引用單一年度數字並註明 n**，不畫趨勢線。

### 5. 分析師報告的引用紀律
- 任何分析師定位必須註明：**報告正式名稱 + 發布日期 + 分析師姓名**
- **Market Guide 沒有 Leader**，只有 "Representative Vendor"
- **Gartner Peer Insights 是客戶評分，不是分析師評測**
- 以下市場目前**沒有 Magic Quadrant**：CNAPP、DSPM、Data Security Platforms、IGA、MDR、SOAR、SSPM、EASM、API Protection、微分段、SD-WAN（現行）、AI Gateway / AI SOC
- 現行市場結構請查 `registry/analyst-reports.yml`

### 6. 語言與術語
- 正體中文，臺灣慣用語
- 英文專業術語、標準編號、法規名稱一律保留原文（不翻譯 CRA、NIS2、SBOM、ZTNA 等）
- 標準引用必須含版本與日期，且註明是 IEC 版或 ANSI/ISA 版（兩者編號不同步）

### 7. 不得聲稱不存在的官方對映
**不存在 NIST 官方發行、經 OLIR 驗證的「CSF 2.0 ↔ IEC 62443」對映表。**
本 repo 的 `controls/*.yml` 中的 62443 對映欄位一律標示為 `mapping_source: self-authored`。

## 資料模型

### controls/*.yml
每個控制項的必要欄位見 `controls/_schema.json`。修改控制項時：
1. 必須同時更新 `frameworks` 對映
2. 必須指定 `owner`（組織功能，非個人姓名）
3. 必須指定 `evidence`（可稽核產出）
4. 若新增外部框架，必須同時更新所有相關控制項的該欄位

### assessments/*/*.yml
自評結果。評分為 0–3（對應 C2M2 MIL）。每個分區（Z1–Z5）獨立評分。
評分變更時**必須填寫 `justification` 與 `evidence_ref`**。

### registry/standards.yml 與 registry/regulations.yml
標準與法規的版本追蹤。每筆必須有 `next_review` 日期。
`freshness-check.yml` workflow 會在 `next_review` 到期時開 Issue。

## 常用任務

當我要求以下事情時，請這樣做：

### 「更新某個標準的版本」
1. 用 WebFetch 存取該標準的**官方頁面**（ISO、IEC、NIST CSRC、EUR-Lex 等），不要用二手來源
2. 更新 `registry/standards.yml`
3. 用 grep 找出手冊中所有引用該標準的位置並更新
4. 若版本變更影響控制項對映，同步更新 `controls/*.yml`
5. 在 commit message 中列出所有變更的檔案與變更理由

### 「查證某個引用」
1. 用 WebFetch 存取原始 URL
2. 確認引述內容與來源一致（逐字比對關鍵數字與日期）
3. 若不一致，**不要自行修正數字**，而是在 `registry/verification-gaps.yml` 記錄矛盾並回報給我
4. 若 URL 失效，尋找官方的替代 URL；找不到則標記為 `[dead-link]` 並降級為【尚未證實】

### 「做落地評估」
見 `assessments/_questionnaire.yml`。逐題詢問，每題必須取得 `evidence_ref`（證據文件、系統截圖位置、報表名稱）。
**沒有證據的自評分數一律以低一級記錄，並在 `justification` 中註明「自評無證據」。**

### 「產生政策文件」

### 「產生對映矩陣」

矩陣頂端必須自動加上「本矩陣為本手冊自行編製，非官方對映」的聲明。

1. 不要為了讓文件看起來完整而編造來源或 URL
2. 不要把【廠商主張】的數字寫成【已證實】
3. 不要在 GitHub Actions 中使用版本標籤（`@v4`）釘選 Action，一律用 commit SHA
4. 不要在 workflow 或 script 中輸出環境變數或 secrets

6. 不要修改 `registry/incidents.yml` 中已標記 `verified: true` 的事件，除非有新的一手來源
7. 不要在沒有我明確確認的情況下 push 到 main 分支

F.4.2 缺口優先排序 Prompt

1. 有外部截止日的合規項（讀取 registry/regulations.yml）— 最優先，不可延後
2. 對應到手冊「常見失敗模式」中影響最大的十項者

1. 立即行動（30 天內，通常是合規截止日與高風險無補償控制項）
2. 短期（Q1–Q2）
3. 中期（Q3–Q4）
4. 長期（次年以後）

          import yaml
          from jsonschema import Draft202012Validator

          schema = json.load(open('controls/_schema.json'))
          validator = Draft202012Validator(schema)
          errors = 0
          ids = set()
          for path in glob.glob('controls/*.yml'):
              data = yaml.safe_load(open(path))
              for ctrl in data.get('controls', []):
                  for e in validator.iter_errors(ctrl):

                  if fw.get('iec62443') and ctrl.get('mapping_source') != 'self-authored':
                      print(f"{path}:{cid}: IEC 62443 mapping must set mapping_source: self-authored")
                      errors += 1
          sys.exit(1 if errors else 0)
          PY

F.9 使用本套件的三個注意事項

  1. repo 必須是 private。它包含集團的控制項現況、自評分數與缺口清單——這對攻擊者是高價值情報。建議另設 branch protection、required reviews 與 CODEOWNERS。

    • 定期檢視 repo 的 Actions 使用清單，移除不再需要的
